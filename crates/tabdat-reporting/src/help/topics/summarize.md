# summarize

How to invoke:
`summarize [varlist]` or `summarize [varlist] if <predicate>` (no options)

What it does:
Show descriptive statistics for one or more numeric variables. Each variable uses its own
finite, non-NULL sample: count, mean, sample SD, minimum and maximum all exclude SQL NULL,
NaN and positive/negative infinity. Sample SD uses N-1 and is undefined below two observations.
An empty finite sample has count zero and undefined mean/SD/extrema. Finite arithmetic overflow
can still fail native aggregates; this is not a general numerical-stability guarantee.
`missing` counts SQL NULL only and can therefore report a larger nonmissing count.

`--json` batch/scripts support `SummarizeResult` with ordered `data.rows` containing
`variable`, `count`, `mean`, `std_dev`, `minimum`, and `maximum`. Explicit variable order
and duplicates are preserved; omitted variables select numeric columns in schema order.
Missing/undefined and non-finite statistics serialize as null. Extrema use the existing
preview scalar encoding (integer numbers, exact scaled decimal strings).

What problem it answers:
How are the variables distributed, and how much missingness is there?

Examples:
- `summarize`
- `summarize age bmi`
- `summarize age bmi if sex == 'F'`

Conditional notes:
- The bounded predicate selects TRUE rows only (FALSE/UNKNOWN excluded), then every aggregate uses that variable's finite/non-NULL sample within selected rows. Counts can differ across variables; this is not a joint/listwise model sample or a reported global matched count. No temporary filtering or named-table publication occurs.
- Predicate rules match bounded `keep if`: comparisons/arithmetic, quoted names/string literals, Boolean columns and SQL-NULL equality. Direct nonfinite comparisons remain native; safe arithmetic can yield NULL/UNKNOWN for nonfinite/failed arithmetic. For example, native NaN can satisfy `x > 0`, but never contributes to x's finite summary; it may contribute to another variable's selected finite sample. `(x + 0) > 0` excludes nonfinite x. Stored empty strings remain distinct from NULL.
- Numeric truthiness/functions/logical-expression breadth and all summary options (`detail`, `limit`, etc.) remain uninstalled. Option-bearing queries are rejected before JSON execution; grouped means remain outside CLI JSON admission. A trailing comma without options is a parse error.
- Success/failure retains data/schema/source/order, labels, named ownership and original cached model/inference/sample. Explicit fitting after inspection uses the unchanged data. Result fields/scalar policy and native finite-arithmetic overflow limits are the same as ordinary summarize. Native query failure stops the command without publishing a partial result. Output write/flush failure stops later effects/files; completed effects are retained (MIG-0008).
- Independent reference: `tests/fixtures/conditional-summary-reference.json`, regenerated by development-only `tools/capture_conditional_summary_reference.py` with NumPy/SciPy; no production dependency.
