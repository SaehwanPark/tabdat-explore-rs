## What was built (the slice)
A two-crate ReadStat DTA ingestion spike under `spikes/readstat-prototype/`:

- **`readstat-sys/`** — the ONLY place with `unsafe`/FFI. Builds the pinned
  ReadStat v1.0.0 from the vendored tarball via `build.rs`, declares the raw C
  ABI, and exposes a safe `parse_dta()` returning owned Rust values.
  `#![deny(unsafe_op_in_unsafe_fn)]` crate-wide; every `unsafe` block has an
  adjacent `// SAFETY:` rationale.
- **`src/lib.rs` (crate root, `tabdat-readstat-spike`)** — a
  `#![forbid(unsafe_code)]` safe facade that re-exports the owned result types
  and forwards to `parse_dta()`. The compiler enforces that no foreign pointer,
  parser handle, or C string appears here.
- **`tests/dta_ingestion.rs`** — 7 integration tests (oracle fixture, variable
  labels, value-label sets, missingness, error cases, repeated parse). All pass.
- **`fixtures/labeled.dta`** — generated by `generate_labeled_dta.c` using the
  ReadStat writer API (pandas cannot write tagged missing values). Carries
  variable labels, a numeric value-label set, a string value-label set, system
  missing, and tagged missing (`.a`/`.b`).
- **`fixtures/patients.dta`** — generated with pandas to match the Python
  oracle's `sample_dta` fixture.

## Key decisions (recorded in the feasibility report)
- **Two-crate split** because `#![forbid(unsafe_code)]` at the crate root would
  conflict with FFI in a single crate.
- **`extract_*` helpers are safe `fn`** (not `unsafe fn`): they take raw pointers
  but centralize the unsafe internally; callers need no `unsafe` block.
- **String value-label keys are a ReadStat limitation:** the writer stores `0`
  for every string key; the reader delivers that raw int32. Tests assert
  `Int32(0)` for both keys with a documentation comment.
- **Missing strings arrive as empty strings** (no missing flag).
  `DtaValue::is_missing()` does NOT flag empty strings; that interpretation is a
  TabDat data-semantics decision, not a ReadStat one.
- **Callback order:** metadata → variables → data rows → value labels. The
  variable handler's 3rd param carries the label-set name (no
  `readstat_variable_get_label_set` accessor).
- **New Apple Clang finding:** `-Wno-implicit-const-int-float-conversion` is
  required for `src/sas/readstat_sas.c` (in addition to the previously recorded
  `-Wno-strict-prototypes` and `LIBS=-liconv`).
